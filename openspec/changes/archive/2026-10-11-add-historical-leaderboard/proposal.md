# Proposal

## Why

目前每局成績只留在結算畫面，玩家無法比較歷史紀錄或留下名字。新增共享歷史前十名，讓玩家看見挑戰目標與差距，並在符合資格時留下本局紀錄，增加重玩動機。

## What Changes

- 首頁在啟動攝影機按鈕下方提供「歷史排行 TOP 10」，不用啟動攝影機即可瀏覽。
- 結算區顯示歷史前十名、本局預估名次或超越第十名所需分數，以及森林風格的情境對白。
- 只有符合前十名資格才顯示留名及送出；空白姓名使用「不知名的勇者」。不登入，每局獨立，不按姓名合併。
- 分數遞減、同分較早提交者優先；滿十筆後必須超過第十名才能提交。送出時重新檢查，處理並發、重試與重複送出。
- 使用 Supabase 保存資料與執行受控後端操作，保留 GitHub Pages 網址與部署；提供載入、空榜、錯誤、重試及未設定服務狀態。
- 視覺延續森林、暖色面板與木牌語彙，兼顧手機及鍵盤操作。
- 不在此變更加入帳號、每人最高分、週榜、管理後台、Vercel 遷移或完整防作弊系統；不改動既有遊戲計分與攝影機隱私。

## Capabilities

### New Capabilities

- `historical-leaderboard`: 公開歷史前十名、匿名留名、資格檢查、差距對白、資料持久化及失敗恢復。

### Modified Capabilities

無。既有 `arcade-session` 結算與 `forest-presentation` 視覺要求保持有效，新增排行榜行為集中於新能力規格。

## Impact

- 前端：`src/main.ts` 首頁及結算整合、`src/style.css`，新增排行榜資料存取、狀態與介面模組。
- 後端：新增 Supabase SQL migrations、受控 RPC 與公開 Edge Function；加入資料驗證、最小資料權限及提交節流。
- 部署：GitHub Actions 注入公開 Supabase endpoint 設定；秘密只放 Supabase。資料庫與函式需另外部署。
- 驗證：新增排名／文案單元測試、資料庫交易與權限測試、瀏覽器互動及正式子路徑驗證。
- 外部前置：實作階段需確認可用 Supabase 專案及部署權限；目前尚未確認已有專案，不能將本機 mock 通過視為正式串接完成。
