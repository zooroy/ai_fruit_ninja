# Design

## Context

現有目錄只有 OpenSpec、技能與 Python 虛擬環境，沒有應用程式、套件宣告或測試；這是全新前端設計。動機及產品範圍見 proposal.md。使用者確認筆電與固定手機、左右食指雙刀、30 秒、炸彈扣分繼續玩，以及參考圖的 low-poly 森林風格。

計分、連切窗口、分數下限、收刀方式及暫停政策是本提案補齊的初始預設，並非使用者逐項指定。規格採用這些可驗證的預設，後續若改變可見行為需同步規格。

## Goals / Non-Goals

**Goals:** 將追蹤、純遊戲規則與渲染分離；手勢與碰撞共用座標；用實機驗證手機雙手模式，規則可用合成輸入自動驗證。

**Non-Goals:** 不處理手向鏡頭前後伸出的深度切割、不用真實網格布林運算、不依赖伺服器推論，不承諾所有手機與嵌入式瀏覽器相容。

## Decisions

### 前端架構

選擇 Vite + TypeScript、Three.js 與 MediaPipe Tasks Vision，使用一般 DOM 建立 HUD，避免為少量介面引入大型應用框架。相較 Canvas 2D，Three.js 更直接表達參考圖的立體低多邊形風格；相較原生 App，共用網頁符合兩種裝置需求。實作時鎖定相容版本、模型與 WASM 資源，隨靜態站點提供並記錄來源及授權。沒有後端、登入或影像上傳。

模組界線：camera 管理串流；tracking 產生帶時間戳與穩定 ID 的手勢輸入；game 管理時間、物件、命中、計分；scene 消費遊戲事件呈現 3D；ui 管理設定、HUD、錯誤及結果。純規則不依賴攝影機或 WebGL。

### 追蹤與座標

設定最多兩隻手。食指伸直以指節角度及手掌尺度判斷，加入啟用／停用遲滯，不要求其他手指固定姿勢。指尖位置做輕度平滑，閾值集中配置並以實機調整。以相鄰影格位置及 handedness 作配對，不以偵測陣列順序當身分；配對不確定或位移不合理時直接斷線，避免跨手刀光。

採鏡像預覽，將影像裁切、比例與鏡像轉換統一映射到標準化遊戲平面，再轉成顯示及碰撞座標。追蹤中斷、收刀或旋轉後，第一筆位置只建立起點。有效相鄰位置以線段掃過目標圓形範圍，避免快速揮動穿透。長時間採樣缺口視為中斷，不能補成巨大切割線。

推論與渲染分開排程，最多一個推論在途，過時影格直接丟棄。優先在 Worker 執行推論；若目標瀏覽器的傳輸／執行路徑不適用，採限制頻率的主執行緒回退並實測。這比每次渲染都同步推論更能控制負載。技術參考：MediaPipe 官方 Hand Landmarker Web 文件 https://developers.google.cn/edge/mediapipe/solutions/vision/hand_landmarker/web_js 。

### 遊戲時間與狀態

流程為 welcome -> loading -> tutorial -> countdown -> playing -> results；錯誤可重試，playing 可進 paused。以單調時間計算有效遊戲秒數，不以影格數或 setInterval 累減。隱藏頁面及串流中斷暫停；短暫看不到手不暫停。30 秒到期先封鎖新命中，再結算此前有效連切。重玩完整清除事件與狀態，結算或離開停止串流。

### 計分初始預設

水果 +10，炸彈 −50，最低 0，漏接無懲罰。每條刀光首顆水果命中開啟固定 300 ms 窗口，窗口採半開區間；3 顆以上額外 +5n。窗口屆滿／收刀／追蹤中斷／到期結算；炸彈或系統暫停取消未結算組。同一刻先水果基本分，後炸彈與取消連切，再處理窗口結算。多顆炸彈逐顆扣分；已給的連切獎勵不追回。

物件具唯一 ID 與 consumed 狀態，兩刀同幀命中只處理一次；以最早交點時間決定歸屬，同時時以穩定刀光 ID 決定，避免隨陣列排序改變結果。左右組不合併。最大連切數記錄成功結算且至少 3 顆的組，沒有則 0。

### 場景與物件

固定鏡頭、3D 視覺搭配共同 2D 遊戲平面。背景放多面體樹木、小屋、草地、柔和陰影與暖光，中央保留低干擾空間。先做至少三種輪廓明確的水果與黑色帶引信炸彈。水果以預製半邊網格含果肉表面呈現切開，依刀光方向旋轉及施加分離速度；相較任意網格切割可降低手機成本。

採有界波次生成、拋物線與可調難度曲線，所有目標經過可視操作區；允許玩家收刀避雷，不安排必須雙手才能完成的情境。畫質降低陰影、粒子上限、背景數量與像素比，不改計分與目標判定。音效在使用者操作後啟用並提供靜音。

### 相容性與驗證

初始實機矩陣為筆電 Chrome、Android Chrome、iPhone Safari；以驗證當時版本及實際裝置記錄，不宣稱未測機型通過。手機建議橫放但直向仍可遊玩。HTTPS 測試前鏡頭、授權拒絕、切換應用程式、旋轉及兩手交叉。效能目標是測試裝置連續三局渲染至少約 30 FPS、刀光可感延遲目標低於 150 ms；記錄實測及量測方式，未達標先降畫質／推論負載，不把自動化模擬當成實機通過。

## Risks / Trade-offs

- 雙手遮擋導致身分跳動 → 不確定時斷線，先驗證交叉、離開與重新進入。
- 手機推論、渲染及散熱競爭 → 限制在途推論、像素比與效果，測連續三局。
- 食指姿勢閾值對不同手型敏感 → 提供試切與明確刀光狀態，用不同距離與光照調整。
- 前鏡頭視野不足 → 放置引導與鏡像預覽；不要求玩家後退到難以看清手機。
- 預製切半無法完全對應任意切面 → 以旋轉與果汁回饋換取可預期成本。
- 參考圖並非可直接發布的資產 → 以描述作美術指引，自製幾何及記錄外部資產授權。

## Migration Plan

無既有資料或服務需遷移。先在本地完成純規則與模擬輸入驗證，再於安全來源進行實機驗證；部署為後續獨立授權工作。若已發布版本出現問題，以靜態版本回退；本提案不執行發布。

## Open Questions

- 最終水果種類、音色與刀光配色可在同一美術方向內調整。
- 食指角度、平滑強度與波次速度須由實機試玩定值，不改上述規則契約。
