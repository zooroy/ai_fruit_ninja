# Proposal

## Why

2026-10-11 使用者以手機實測正式網址，回報結算與排行版面太擠、需要捲動，遊戲本身在手機上的操作體驗也不佳。現行規格卻要求支援手機橫直向，且「不得因直向而禁止遊玩」。在找到可行的手機設計之前，先把支援範圍收斂到桌機與筆電，避免玩家在未驗證的裝置上得到不佳體驗。

## What Changes

- **BREAKING**：手機與平板（以觸控為主要輸入的裝置）不再支援遊玩。首頁以森林風格說明「請改用電腦遊玩」，取代啟動攝影機按鈕；不要求攝影機權限，也無法進入試切或遊戲。
- 不支援的裝置仍可從首頁開啟「歷史排行 TOP 10」唯讀瀏覽，不提供留名。
- 判斷依據為瀏覽器回報的主要輸入方式（觸控且無滑鼠懸停），不使用 User-Agent 或螢幕寬度；觸控筆電與縮小的桌面視窗仍可遊玩。
- 桌面縮小視窗（窄或矮）的響應式版面保留，維持可讀可操作。
- 移除「手機優先使用前鏡頭」、「直向手機可開始遊戲」、「直向手機查看榜單」等規格條款，改以桌面窄視窗驗收。
- README、驗收文件與 E2E 改為桌面窄視窗與觸控裝置被擋下的情境；手機實機矩陣不再列為待驗項目。

## Capabilities

### New Capabilities

無。

### Modified Capabilities

- `forest-presentation`：響應式需求改為桌機與筆電（含窄、矮視窗）；新增不支援裝置的說明畫面需求。
- `gesture-input`：攝影機設定移除手機前鏡頭條款，並規定不支援的裝置不得要求攝影機權限。
- `historical-leaderboard`：版面驗收由直向手機改為桌面窄視窗；不支援的裝置仍可唯讀瀏覽首頁排行。

## Impact

- 前端：`src/main.ts` 啟動流程與首頁、`src/style.css`，新增裝置判斷模組；`src/ui/leaderboard.ts` 不需改動，首頁排行沿用。
- 測試：新增觸控裝置被擋下的單元測試與 E2E；既有 390×844、844×390 測試改述為桌面窄／矮視窗，並更新截圖名稱。
- 文件：README 遊玩方式與 HTTPS 手機說明、`docs/verification.md` 的手機實機矩陣。
- 後端：無影響。Supabase 與 Edge Function 不分裝置，手機仍可透過 API 讀取榜單。
- 既有規格的 Purpose 段落仍提及手機；delta 只能修改需求，Purpose 需在封存同步時另行處理。
